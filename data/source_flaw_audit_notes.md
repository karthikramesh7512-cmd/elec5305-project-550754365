# Source flaw audit evidence

Input: `metadata.csv`. Reproduce with `python audit_source_flaws.py` from the project root.
Only `has_flaw == 1` rows are grouped. The input CSV is not modified.
`original_size` preserves the existing `flaw_size` field exactly; `flaw_depth_values`
contains unique values of `depth`. Depth units remain unknown.

## Directly encoded metadata

All six P41 labels have exactly one original size and depth each, in every batch
013 through 019. Their counts total 3,442. Two labels share size 6, so size alone
does not distinguish the experimental sources.

Simulated positives total 5,018. The six raw size groups are 0.001, 1.001, 2.001,
3.001, 4.001 and 5.001; every group occurs in all batches 201 through 210.
`sim_raw_*` names are generated by this audit, not present in the metadata.

## Paper evidence and uncertainty

[Koskinen et al. (2021)](https://doi.org/10.1007/s10921-021-00757-x), Sections
2.1–2.3, describes scanned sizes 2, 3, 6, 6, 17 and 26 mm, and six simulated
notch heights of 1–6 mm. This supports the experimental inventory and six
simulated categories, but does not document the raw-value encoding.

The ordered correspondence 0.001 -> 1 mm, ..., 5.001 -> 6 mm is a hypothesis.
It is stored only in `candidate_notch_size_mm`; `paper_supported_size_mm` stays
null for simulations. A generation-code lookup or author confirmation is needed
before treating that correspondence as verified.

Table 2 reports 4,982 simulated flaw images, whereas this CSV has 5,018 positives.
The discrepancy is unresolved and prevents using the published total as validation.
The paper's experimental total (3,442) matches this CSV.

P41 physical identities are supported by matching inventory, but no explicit P41
codebook is supplied. The original CSV's non-2xx experimental designation was
inferred; the scanned-data inventory provides supporting context.

No models were trained and no train/test splits were created.
